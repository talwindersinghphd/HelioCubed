# FullSphere: SWQU tutorial

FullSphere evolves MHD on a spherical latitude–longitude grid. This tutorial uses time-dependent solar-wind boundary frames generated by SWiG.

## Building

Use C++17, MPI, parallel HDF5, and Proto's `integrate/master-cubedSphereDev` branch. `PROTO` points to the Proto checkout; it defaults to `../../proto` relative to `exec/`. The port was validated against Proto `01ad5408` with its two header-defined `LEVELRK4_STAGE` and `LEVELRK4_ITER` diagnostics changed to C++17 `inline` variables in `include/utils/Proto_LevelRK4.H`. That small Proto fix is required to link FullSphere's multiple translation units.

FullSphere now owns its generic RK4 integrator in `src/MHD_RK4.H`; the old Proto `CommonTemplates.H` and `RK4.H` example headers are no longer required. `InputParser.H` and `PolarExchangeCopier.H` still come from Proto's `examples/_common/`.

Set the HDF5 and LAPACK/BLAS paths for your machine. For the Homebrew MPI libraries used here:

```sh
make -C exec -j8 PROTO=../../proto \
  HDF5_INC=/opt/homebrew/opt/hdf5-mpi/include \
  HDF5_LIB=/opt/homebrew/opt/hdf5-mpi/lib \
  LAPACK_LIB='-L/opt/homebrew/opt/openblas/lib -lopenblas'
```

Release builds enable `NDEBUG` and omit redundant host Copier barriers. Boundary-file reads, HDF5 validation, and input checks remain active. For an assertion-enabled build, use `DEBUG=1`. Clean first when changing build flags, or use separate `OBJDIR`, `DEPDIR`, and `TARGET` paths:

```sh
make -C exec clean
make -C exec -j8 DEBUG=1 \
  LAPACK_LIB='-L/opt/homebrew/opt/openblas/lib -lopenblas'
```

## Boundary files

The tracked `BC_files/` datasets are tutorial inputs. Convert the SWiG frames into one HelioCubed HDF5 file:

```sh
cd scripts
python3 SWiG_to_HelioCubed_h5_conversion.py
cd ..
```

The converter produces `scripts/SWQU_Tutorial_SWiG.h5` and a first-frame-only file. To use that conversion, set `BC_file` in `exec/inputs` to `../scripts/SWQU_Tutorial_SWiG.h5` and set the corresponding boundary start time and frame cadence. The supplied inputs currently select the separate, provided two-frame eclipse boundary file.

HDF5 angular sizes must be integer multiples of the simulation's phi and theta sizes. The reader averages to the requested resolution, transposes to the solver's storage order, and repeats the phi period for rotation. Missing or malformed files are reported in both release and debug builds.

## Running and viewing results

Edit `exec/inputs`, then run:

```sh
cd exec
mpirun -n 8 ./FullSphere.exe inputs
```

Each domain size must be divisible by `BoxSize`. Polar exchange also requires an even number of azimuthal cells and patches. Available integrators are Euler (1), explicit midpoint RK2 (2), MUSCL–Hancock (3), and classical RK4 (4).

### Co-rotating frame

To evolve in a frame rotating with the Sun, set these options in `exec/inputs`:

```text
-corotating_frame                1
-solar_rotation_period           25.38
```

`corotating_frame` defaults to `0` for the inertial solver. `solar_rotation_period` is the sidereal rotation period in days and defaults to `25.38` when omitted. The same period controls inertial boundary rotation, rotating-frame forces, and probe transformations, with angular velocity `Omega = 2*pi/(solar_rotation_period*86400)` about the positive z axis. In a co-rotating run, boundary maps stay at their supplied longitudes regardless of `BC_frame_rotate`. Multiple maps still interpolate in time using `BC_cadence`; a single map or the final map is held fixed. Time-dependent maps must share a common co-rotating longitude grid.

The momentum source is `rho * [(Omega x r) x Omega + 2 (v x Omega)]`, and the energy source is its work `v . F`. Coriolis does no work, so only the centrifugal contribution enters energy. Sources are included independently of `Sun_gravity` in every Euler/RK evaluation and in both Hancock stages. Coordinates remain in cm; the sources use `Omega / velocity_scale` to match the solver's scaled time and velocities. The Cartesian form avoids divisions by `sin(theta)` at the poles.

Boundary velocities are used as supplied and interpreted in the selected simulation frame. The analytic initial state and analytic inner boundary likewise specify velocities in that frame. For an inertial boundary dataset, convert its azimuthal velocity to `v_phi - Omega*r*sin(theta)` before using it in a co-rotating run. Volume output and checkpoint velocities remain in the simulation frame; restart with the same frame and rotation period. CME input longitudes and velocity components also refer to the simulation frame. Probe trajectories retain their existing inertial longitude convention: sampling accounts for grid rotation, and probe velocities are converted back to inertial values for comparison with observations.

Run the rotation source, boundary interpolation, and probe regression checks with `make -C exec test-rotation`, supplying the same Proto and library paths as for a solver build. Use separate object directories when testing both `TURB=0` and `TURB=1`.

Plot a generated probe file with:

```sh
cd ../scripts
python3 Plot_sim.py
```

To visualize the generated HDF5 files in VisIt, create a vector mesh expression named `disp`:

```text
{X,Y,Z}-coord(Mesh)
```

Python environments (`.venv/`, `.venv.nosync/`), caches, build products, local test helpers/results, and run directories are ignored by Git. The provided boundary datasets and probe trajectory remain tracked inputs.
